# Работа с офисными документами

Ты готовишь и правишь офисные файлы (docx, xlsx, pptx, pdf) для пользователя. Твоя цель — результат, который не стыдно открыть: единая типографика, ничего не переполнено и не разъехалось. Текстовый успех инструмента ещё не значит, что документ выглядит правильно — правильность подтверждается только глазами.

## Когда применять

- Пользователь просит создать документ, отчёт, таблицу, презентацию или PDF.
- Нужно отредактировать существующий файл (в том числе присланный пользователем — в облачном компьютере такие лежат в `/workspace/attachments`).
- Нужно конвертировать формат, собрать/разбить PDF, распознать текст (OCR), заполнить форму.

## Порядок работы

1. **Пойми исходник.** Если файл уже есть, вызови `read_document` — он вернёт Markdown-проекцию структуры и метаданные. Это и есть единственный способ прочитать PDF или офисный файл: напрямую модели такие файлы не передаются, и `view_media` на них отвечает отказом. Не редактируй вслепую и не пересоздавай документ с нуля, если пользователь просил именно правку.
2. **Никогда не перезаписывай оригинал пользователя.** Присланные файлы — исходники. Работай с копией: у edit-инструментов задавай `outputPath`, у новых файлов — путь в `artifacts/documents` рабочей папки (в облачном компьютере — `/workspace/artifacts/documents`). Не пиши результат обратно в папку вложений.
3. **Выбери правильный инструмент под формат** (не реализуй это через `execute_command` и библиотеки вручную):
   - docx: `create_document` (из Markdown), `edit_document` (режимы `patch` — точечные операции, `rewrite` — из нового Markdown).
   - xlsx: `create_workbook` (листы, ячейки, формулы, стили, фиксация областей, фильтры), `edit_workbook` (`set_cell`, `set_range`, `append_rows`, `add_sheet`, `replace_text` и др.), `export_table` (в csv/tsv).
   - pptx: `create_presentation`, `edit_presentation` (для структуры и дизайна слайдов активируй навык `presentation-design`).
   - pdf: `create_pdf` (из секций), `edit_pdf` (extract/split/rotate/watermark/encrypt и др.), `combine_pdfs`, `inspect_pdf_form` + `fill_pdf_form`, `ocr_pdf`.
   - смена формата: `convert_document` (по расширениям source/target).
4. **Правь точечно.** Для существующих файлов предпочитай `patch`-операции и адресные правки (`replace_text`, `set_cell`, `append_slides`) вместо полного `rewrite` — так сохраняется остальное содержимое и стиль.
5. **Рендери и проверяй глазами после каждой значимой правки.** Вызови `read_document` с параметром `renderPages` (например `"1-3"` или `"1"`) — он отрендерит страницы в PNG (`pageImages`). Затем `view_media` по каждому изображению: убедись, что вёрстка не переполнена, таблицы не обрезаны, заголовки на месте, шрифты единообразны. Если выбранная модель не видит изображения сама, `view_media` вернёт текстовое описание страницы — тогда обязательно передавай `question` с тем, что нужно проверить («переполнены ли ячейки таблицы», «влез ли заголовок в одну строку»). Успех инструмента ≠ корректный документ.
6. **Финализируй.** Дай пользователю человекочитаемое имя файла и путь. Метаданные артефакта смотри через `list_workspace_files` или `describe_workspace_file`.

Практические рецепты по docx и xlsx (стили, заголовки, таблицы, формулы, числовые форматы) — в `references/recipes.md`, читай через `skill_read`, когда нужны конкретные приёмы.

## Чеклист качества

- [ ] Исходник прочитан через `read_document` до правок; оригинал в `attachments` не тронут.
- [ ] Правки сделаны специализированными edit-инструментами, а не пересозданием с нуля.
- [ ] После правок страницы отрендерены (`read_document` + `renderPages`) и просмотрены через `view_media`.
- [ ] Типографика единообразна: один шрифт тела, один — заголовков, согласованные размеры.
- [ ] Нет переполнений: текст не вылезает за поля, таблицы и колонки не обрезаны.
- [ ] Числа в таблицах имеют осмысленный числовой формат, формулы считаются.
- [ ] Файл лежит в `artifacts/documents`, имя человекочитаемое.

## Частые ошибки

- **Доверять текстовому «успешно» без визуальной проверки.** Инструмент вернул ok, а таблица уехала за край страницы — заметно только на рендере.
- **Пересоздавать документ вместо точечной правки.** Теряются стили, разметка и то, что пользователь не просил менять.
- **Писать результат поверх вложения пользователя.** Всегда отдельный `outputPath`.
- **Собирать docx/xlsx/pdf вручную через код в сэндбоксе.** Для этого есть инструменты документов — они дают консистентный результат.
- **Оставлять машинные имена файлов** вроде `output-1.docx`. Дай осмысленное название.
