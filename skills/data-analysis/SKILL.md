# Анализ данных

Ты превращаешь данные пользователя в выводы. Правило номер один: сначала пойми данные (профилирование), потом анализируй. Любое решение по чистке данных влияет на результат — фиксируй и озвучивай его. В выводах отделяй то, что показывают данные, от своей интерпретации.

## Когда применять

- Пользователь дал датасет (CSV, JSON, xlsx — вложением или файлом в папке проекта) и хочет анализ, метрики, срезы или графики.
- Нужно проверить гипотезу на данных, найти закономерность, аномалию, тренд.

## Порядок работы

1. **Найди и загрузи данные.** Среду определи сам: если рабочая папка — `/workspace` и доступен инструмент `neurium_service`, ты в облачном компьютере Нейриума — вложения лежат в `/workspace/attachments` (индекс `/workspace/attachments/manifest.json`), python с pandas/matplotlib гарантированно есть; если работаешь в папке проекта на машине пользователя (Neurium Desktop: macOS, Windows или Linux) — данные там, куда указал пользователь, а python может отсутствовать или быть без пакетов. Табличные и текстовые файлы читай через `read_file`; структуру xlsx можно осмотреть `read_document`, а выгрузить лист в csv — `export_table`. Основной анализ веди в python через `execute_command`. На машине пользователя перед первым запуском проверь: `python3 --version` (на Windows — `python --version`) и `python3 -c "import pandas, matplotlib"`; пакетов нет — ставь в виртуальное окружение проекта (`python3 -m venv .venv` → `.venv/bin/pip install pandas matplotlib openpyxl`; на Windows `.venv\Scripts\pip`) или `pip install --user`, без `sudo`. Если python поставить нельзя — честно скажи пользователю, что нужно, и считай тем, что есть (node-скрипт, формулы в xlsx через `create_workbook`, для маленьких таблиц — аккуратный расчёт в чате с показом чисел), не подменяя воспроизводимость догадками.
2. **Сначала профилируй, только потом анализируй.** До любых выводов посчитай:
   - размер (строки × колонки), типы колонок;
   - пропуски по колонкам, доля пустых;
   - дубликаты строк;
   - для чисел — min/max/среднее/медиана, очевидные выбросы;
   - для категорий — число уникальных значений, топ значений.
   Без профилирования не строй выводы — иначе анализируешь мусор.
3. **Чисти осознанно и вслух.** Каждое решение (удалить строки с пропусками, привести типы, отфильтровать выбросы, дедуплицировать) фиксируй и озвучивай пользователю с причиной и количеством затронутых строк. Не выбрасывай данные молча.
4. **Считай и визуализируй.** Строй графики через matplotlib, сохраняй в png в папку артефактов проекта (в облачном компьютере — `/workspace/artifacts/images`). Обязательно проверяй каждый график через `view_media`: подписаны ли оси, читаемы ли легенды, не обрезаны ли метки, тот ли тип графика.
5. **Формулируй выводы честно.** Явно разделяй «данные показывают X» и «возможное объяснение — Y». Указывай ограничения: размер и репрезентативность выборки, период, качество данных, что осталось непроверенным. Не делай выводов за пределами того, что есть в данных.
6. **Отдай результат.** Итоговые таблицы для пользователя оформляй в xlsx через `create_workbook` / `edit_workbook` (осмысленные числовые форматы, шапка). Краткие выводы — в чат, с ссылками на артефакты.

Готовые сниппеты профилирования и чистки на pandas — в `references/pandas-recipes.md` (читай через `skill_read`).

## Чеклист качества

- [ ] Данные профилированы (размер, типы, пропуски, дубликаты, выбросы) до анализа.
- [ ] Каждое решение по чистке зафиксировано и озвучено с числом затронутых строк.
- [ ] На машине пользователя наличие python/pandas проверено до первого запуска; пакеты ставились в venv/`--user`; без python — пользователю сказано, чего не хватает, и выбран честный путь без него.
- [ ] Графики сохранены в папку артефактов проекта и проверены через `view_media`.
- [ ] У графиков подписаны оси и легенды, метки не обрезаны.
- [ ] В выводах «данные показывают» отделено от интерпретации.
- [ ] Указаны ограничения выборки и то, что осталось непроверенным.
- [ ] Итоговые таблицы отданы в xlsx с числовыми форматами.

## Частые ошибки

- **Анализ без профилирования.** Скрытые пропуски, дубликаты и неверные типы искажают всё.
- **Молчаливое выбрасывание строк.** `dropna()` без отчёта — потерянные данные, о которых пользователь не знает.
- **Выводы за пределами данных.** Корреляция — не причинность; малая выборка — не популяция.
- **Непроверенные графики.** Обрезанная легенда или неверный тип графика вводят в заблуждение — смотри через `view_media`.
- **Считать в уме или на глаз** вместо воспроизводимого кода через `execute_command`.
- **Запускать pandas вслепую на машине пользователя** — интерпретатора или пакетов может не быть; сначала проверь, ставь в venv/`--user`, при невозможности — честно объясни и считай доступными средствами.
