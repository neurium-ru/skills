# Дизайн презентаций

Это надстройка над навыком работы с офисными документами для pptx. Механику инструментов бери там (`create_presentation`, `edit_presentation`), а здесь — как сделать презентацию, которую приятно смотреть. Презентация — это история, а не свалка текста на слайдах.

## Когда применять

- Пользователь просит презентацию, слайды, питч, деку.
- Есть готовый pptx, который нужно улучшить по структуре и виду.

## Принципы

1. **Один тезис на слайд.** Каждый слайд несёт одну мысль. Если на слайде две идеи — это два слайда.
2. **Структура-история:** хук (зачем это важно) → аргументы (по одному на слайд) → вывод (что делать дальше). Начни с плана слайдов текстом, прежде чем строить.
3. **Крупная типографика, мало текста.** Заголовок — короткий и крупный. В теле — тезисы, а не абзацы. Контраст размеров создаёт иерархию: заголовок заметно больше подписи.
4. **Ограниченная палитра.** 2–3 цвета максимум, один акцентный. Задай их один раз в общей `theme` (`accentColor`, `background`, `textColor`, `headingFont`, `bodyFont`) и применяй ко всем слайдам — единый стиль важнее разнообразия.
5. **Выравнивание по сетке.** Элементы выровнены, отступы одинаковы. Разнобой в позициях читается как небрежность.
6. **Изображения по делу.** Где иллюстрация усиливает мысль — сгенерируй её через `generate_image` (сохранится в `artifacts/images` рабочей папки; в облачном компьютере — `/workspace/artifacts/images`) и вставь в слайд через поле `image` с путём. Не украшай ради украшения.

## Порядок работы

1. **Спланируй деку** текстом: список слайдов, по одному тезису на каждый, логика хук → аргументы → вывод.
2. **Собери презентацию** через `create_presentation`: общий `theme` + массив `slides`. Подбирай `layout` под смысл слайда — доступны `title`, `section`, `bullets`, `two_column`, `comparison`, `callout`, `process`, `image`, `chart`, `blank` (подробнее — `references/layouts.md`).
3. **Итерируй по слайдам с проверкой глазами.** После сборки — `read_document` с `renderPages` и просмотр каждого слайда через `view_media`. Правь проблемные слайды через `edit_presentation` (`replace_text`, `append_slides`, `delete_slides`, `reorder_slides`, `set_notes`) и снова смотри. Текстовый успех инструмента не гарантирует, что слайд не переполнен.
4. **Проверь всю деку целиком** на единство стиля: одни шрифты, одна палитра, согласованные заголовки.

## Чеклист качества

- [ ] План слайдов составлен до сборки; на каждом слайде один тезис.
- [ ] Логика хук → аргументы → вывод прослеживается.
- [ ] Единая палитра (2–3 цвета) и одни шрифты на всей деке (через общий `theme`).
- [ ] Заголовки крупные, текста минимум, иерархия размеров видна.
- [ ] Элементы выровнены, отступы единообразны.
- [ ] Каждый слайд отрендерен и просмотрен через `view_media`; переполнений нет.
- [ ] Изображения (если есть) усиливают мысль, а не заполняют пустоту.

## Анти-паттерны

- **Стена текста** на слайде — слайд не документ, вынеси детали в заметки (`set_notes`).
- **Буллеты-простыни** из десятка пунктов мелким шрифтом.
- **Разнобой шрифтов и цветов** между слайдами.
- **Два тезиса на одном слайде** вместо двух слайдов.
- **Сборка вслепую** без порендерной визуальной проверки.
