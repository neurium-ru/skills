# Создание навыков

Ты умеешь оформлять свой опыт в новый навык — методику, которой воспользуешься в будущих сессиях. Навык — это переиспользуемая инструкция «как делать класс задач», а не лог одного разговора. Свои навыки живут в `skills/<slug>/` рабочей папки (в облачном компьютере — `/workspace/skills/<slug>/`) и в промте перекрывают одноимённые управляемые.

## Когда предлагать навык

- Пользователь второй-третий раз просит один и тот же процесс — есть смысл его закрепить.
- Пользователь прямо говорит «запомни, как надо», «делай так всегда».
- Ты вывел устойчивую методику под класс задач, которая пригодится снова.

Не создавай навык молча и не делай его из разового частного случая. Предложи — и создавай с согласия.

## Порядок работы

1. **Проверь, нет ли уже такого навыка.** Вызови `skill_search` по теме. Если близкий навык есть — дополни его подход, а не плоди дубль.
2. **Сформулируй границу навыка:** какой класс задач он покрывает и когда активируется. Одна методика — один навык.
3. **Создай директорию и `SKILL.md`** в `skills/<slug>/` (`write_file`). `slug` — латиницей, `[a-z0-9-]`, совпадает с именем директории.
4. **Заполни frontmatter:**
   ```
   ---
   name: <slug>
   description: "<что делает + когда активировать, ≤300 символов>"
   metadata:
     version: "1.0.0"
   ---
   ```
   `name` обязан совпадать с именем директории.
5. **Вложи в тело методику,** не пересказ разговора: когда применять, порядок работы по шагам с точными именами инструментов, чеклист качества, частые ошибки. Императив, обращение «ты» к агенту.
6. **Применяй прогрессивное раскрытие.** Ядро методики — в теле `SKILL.md`. Объёмные детали (рецепты, справочники, длинные шаблоны) выноси в `references/<имя>.md` и ссылайся на них — тело должно оставаться компактным.
7. **Проверь навык активацией.** Вызови `skill` с именем нового навыка и убедись, что инструкция грузится и читается как связная методика. Отдельные файлы навыка проверяй через `skill_read`.

## Про `description` — он решает всё

`description` — единственное, что модель видит про навык ДО активации (в блоке «Доступные навыки»). По нему навык находят и решают активировать. Поэтому он должен одновременно:

- **описывать**, что навык делает;
- **триггерить** — содержать формулировку «Используй, когда …» с ситуациями активации;
- укладываться в **≤300 символов**.

Плохо: «Навык для документов». Хорошо: «Оформление отчётов в docx с проверкой рендера. Используй, когда пользователь просит подготовить или отредактировать документ».

## Чеклист качества

- [ ] `skill_search` показал, что дубля нет.
- [ ] `name` в frontmatter совпадает с именем директории (`slug`, латиницей).
- [ ] `description` описывает и триггерит, ≤300 символов.
- [ ] Тело — методика (шаги, инструменты, чеклист, ошибки), а не лог разговора.
- [ ] Объёмные детали вынесены в `references/`, тело компактно.
- [ ] Навык проверен активацией через `skill`.

## Частые ошибки

- **Записать лог разговора** вместо обобщённой методики.
- **Слабый `description`** без триггера — навык не найдут и не активируют.
- **Дублировать существующий навык** вместо его дополнения.
- **Свалить всё в тело** без прогрессивного раскрытия — раздутый `SKILL.md`.
- **Не проверить активацией** — битый frontmatter или нечитаемая инструкция всплывут уже в работе.
- **Создать навык молча** из единичного случая без согласия пользователя.
